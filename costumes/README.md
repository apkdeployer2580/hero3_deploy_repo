# 아바타 옷장 — 의상 그림 (167차 · 168차)

**PNG 가 정본이다.** 고칠 때는 PNG 를 고친다. 게임 에셋(`res/hero/h…_bm`)은 에셋 체인이
이 PNG 로부터 만들고, 손으로 만지지 않는다. 정본 문서 = `AVATAR_WARDROBE_PLAN.md`.

## 폴더 하나 = 세트 하나

```
costumes/<NN>_<slug>/
    costume.txt          세트 이름 · 획득 방법 · 조각 이름과 설명 (아래)
    helmet_0..3.png      투구   4 프레임
    armor_0..2.png       갑옷   3 프레임 (몸통)
    gloves_0..11.png     장갑  12 프레임 (팔)
    shoes_0..17.png      신발  18 프레임 (다리)
    weapon_<종류>_N.png  무기   spear 6 · sword 5 · knife 4 · gun 6 · rifle 7 · dark 1 · holy 1
    shield_0.png         방패   1 프레임
```

* `NN` = 세트 번호(1..50). **한 번 정하면 바꾸지 않는다** — 세이브가 이 번호를 기억한다.
  게임 파일 이름의 스프라이트 번호는 `49 + NN` 이다(출고 시트는 0..22 를 쓴다).
  ⛔ **지운 세트의 번호도 다시 쓰지 않는다**(01 · 03 은 168차에 은퇴) — 그 번호를 입은 채 저장된
  세이브가 있을 수 있다. 시트가 없는 번호는 게임이 원래 장비로 그리고 페이지는 「기본 외형」으로 읽는다.
* 무기는 **무기 종류마다 따로** 그린다(게임이 종류마다 다른 프레임으로 휘두른다):
  spear = 스피어 · sword = 스워드 · knife = 나이프(손톱/너클) · gun = 건 · rifle = 라이플 ·
  dark = 다크스톤 · holy = 홀리스톤(둘 다 발밑의 마법진 한 장). 그 종류의 PNG 가 없으면 그
  종류의 캐릭터 목록에 그 무기가 안 나온다 — 일부 종류만 그려도 된다.
* 조각 하나가 없으면(PNG 없음) 그 칸의 목록에 안 나온다. 이름(`costume.txt`)이 있어도 그렇다.

## 프레임 크기는 고정이다

게임은 층마다 프레임 **번호와 크기**로 자리를 잡는다. 출고 시트는 같은 그룹이면 프레임
크기가 전부 같고, 의상 PNG 도 그 크기여야 한다(`tools_re/avatar_sheets.py` 의 `FRAME_SIZES`).
**크기를 바꾸지 말고 그 안에 그릴 것.** 다른 크기는 에셋 체인이 거절한다.

가장 안전한 제작법(hero2 와 같다): **출고 시트의 실루엣을 그대로 두고 그 안을 새로 칠한다.**
출고 시트를 PNG 로 꺼내는 법:

    python tools_re/avatar_sheets.py export <그룹> <스프라이트> <폴더>
    # 그룹: 0 투구 · 1 갑옷 · 2 장갑 · 3 신발 · 4..10 무기(스피어..홀리스톤) · 11 방패

## 색

* 인덱스 PNG 든 RGBA PNG 든 읽는다. **투명 = 알파 128 미만**, 나머지는 불투명. 반투명은 없다.
* 색은 게임 형식(RGB565)으로 반올림된다 — 보이는 것과 최대 4/8/4 단계 다를 수 있다.
* 한 프레임에 불투명 색 255 개까지(15 개 이하면 4bpp 로 작게 실린다).
* 피부색은 장갑(손) · 투구(얼굴이 보이는 부분)에서 원래 색을 지키는 편이 자연스럽다.

## costume.txt

```
set          = 세트 이름                     # 정보 칸 143 px 까지
acquire      = starter | clear.normal | clear.hard | clear.hell
helmet       = 조각 이름                     # 목록 칸 96 px 까지 (오른쪽 끝의 착용 표시 E 를 비켜서)
helmet.desc  = 한 줄 설명                    # 143 px 까지
weapon       = 무기 이름
weapon.spear = 스피어로 들 때의 이름          # 없으면 weapon
```

`hero = kei` / `hero = ritz` (168차) = 그 주인공의 옷장에만 나오는 세트. 없으면 둘 다.
주인공은 캐릭터 레코드의 클래스명(`CHAR+0xb8`)으로 가르고, 못 읽으면 어느 주인공 전용 세트도 안 나온다.

글자는 게임 글꼴이 그리는 것만(KS X 1001 한글 · ASCII). 폭은 한글 11 · 공백 5 · `.`/`,` 4 ·
그 밖의 ASCII 8 px. 고친 뒤 `python tools_re/gen_avatar_catalog.py` 로 목록을 다시 만든다
(`--check` 가 낡은 목록을 잡는다).

## 고친 뒤 하는 일

    python tools_re/avatar_sheets.py check            # 크기 · 프레임 수 · 색 수 검사
    python tools_re/gen_avatar_catalog.py --check     # 이름을 고쳤으면 (아니면 그냥 실행)
    # 에셋 체인 여섯 (CLAUDE.md 「에셋을 고칠 때는 도구 셋을 이 순서로」) → 여섯 --check

`tools_re/costume_draft.py` 는 167차 첫 초안(02 이안)을 만든 기록일 뿐이다 — 이미 PNG 가 있는 폴더는
덮어쓰지 않는다(`--force` 는 아무도 안 만진 폴더에만).

## 169차: 모든 세트를 그리는 도구 — `tools_re/costume_atelier/`

사용자 지시(2026-10-07): *"실제로 도트를 새로 전부 찍어야해. 기존에 색만 입히는 느낌으로 하는게 아니야.
기본 아바타들도 전부 다시 만들어줘."* — 그래서 02 · 04~07 을 포함한 **모든 세트를 재채색 없이 프레임마다
새로 그렸다**. 출고 시트는 몸의 자리(다리 · 팔 실루엣과 종이인형 배치)만 빌리고, 옷 · 머리 · 무기의 픽셀은
전부 세트 스크립트의 텍스트 격자에서 나온다. 작업법 = **`tools_re/costume_atelier/ATELIER.md`**.

    python tools_re/costume_atelier/build.py --lint              # 크기 · 색 수 · 머리카락 덮임 · 이름 폭 (전 세트)
    python tools_re/costume_atelier/build.py --check             # 다시 그려서 costumes/ 와 픽셀 대조 (지금 = 11 세트 OK)
    python tools_re/costume_atelier/build.py --out <폴더> [NN]   # 그 폴더에 그려 본다
    python tools_re/costume_atelier/build.py --force [NN]        # costumes/NN_* 를 덮어쓴다 (번호 없으면 전부)
    python tools_re/costume_atelier/preview.py <slug> --out <폴더>   # 주인공에게 입혀 자세 · 게임 크기 · 투구를 PNG 로

* ⛔ **PNG 가 정본인 것은 그대로다.** 손으로 고친 프레임이 생기면 `--check` 가 STALE 을 내고, 그때부터
  `--force` 는 그 수정을 지운다.
* 세트 하나 = `tools_re/costume_atelier/sets/<slug>.py`(NUM · FOLDER · HERO · TEXT · build()).
* ★ **171차 — 투구는 그린 뒤 `helmfit.py` 가 작게 만든다**(사용자: *"머리가 너무큰거같은데 좀만 줄여줄수없어?"*):
  `head = own` 세트(08~13 · 04 · 05)는 주인공 얼굴을 합쳐 넣고 얼굴을 피해 2열 · 2행을 걷어낸다 — 게임은 그 투구를
  입은 동안 주인공 자신의 머리를 안 그린다(훅 `avatar_head_paint_lgt`). 이안(02, 두 주인공 · 얼굴 보임)은 머리 밖
  돌출만 절반으로. 그래서 `costumes/NN_*/helmet_*.png` 는 스크립트의 그림 + 그 처리다(`--check` 가 둘 다 대조).
* 168차 생성기(`tools_re/costume_factory/`)는 기록으로 남겼다 — `build.py --check` 는 「superseded」만 말하고
  `--force` 는 거절한다(새 그림을 덮지 않게). `bmview` · `cif` · `doll` 은 atelier 가 그대로 쓴다.
