# 오디오 검증

Android 재생 코드의 DSP·믹서·사운드폰트를 그대로 불러오는 호스트 검증 도구다. 오디오 장치를 열지 않는다. Windows에서는 설치된 MSVC 도구체인을 사용한다. 이 환경의 GNU 실행기는 rodio를 링크한 테스트 실행 시 시작 단계에서 접근 위반으로 종료됐다.

```powershell
cargo +stable-x86_64-pc-windows-msvc test --manifest-path tools/audio_verify/Cargo.toml --locked
python tools_re/test_patch_bgm_ma3.py
```

전곡 검증은 로컬 게임 jar의 `res/snd` 파일을 임시 디렉터리에 추출한 뒤 실행한다. 게임 음원은 저장소에 추가하지 않는다.

```powershell
cargo +stable-x86_64-pc-windows-msvc run --manifest-path tools/audio_verify/Cargo.toml --locked -- <snd-directory>
```

CSV 출력은 BGM 19곡의 전체 이벤트 구간과 2초 잔향, 효과음 14개를 대상으로 한다. BGM은 이전 44.1kHz·4차 보간과 새 44.1/48kHz·7차 보간을 비교한다. 효과음은 이전 44.1kHz 선형 보간과 새 sinc 변환을 비교한다. 측정값은 게임 볼륨 100 기준, 마스터 리미터 적용 전이다. `--sfx-only`를 추가하면 효과음만 검사한다. BGM RMS 변화 1dB, 효과음 1.5dB를 넘으면 실패한다.

재생 경로:

- BGM: 기존 MA-3 음색·악보·gain 0.38 유지, 기본 7차 보간. 기존 저사양 모드는 선형 보간과 잔향 비활성화를 유지한다.
- 효과음: DC 제거 → Blackman 창 sinc 변환 → 재구성 경계 0.5ms 페이드 → 공유 PCM 캐시 → 기존 버스·클립 음량.
- 캐시는 정확한 PCM·채널·입출력 레이트로 구분하며 샘플 데이터 16MiB, 항목 96개 이내로 유지한다. 처음 쓰는 클립만 오디오 수신 스레드에서 변환한다.
- 일반 출력 레이트에서는 기기 레이트로 합성·믹싱한다. 신스 지원 범위 밖의 장치는 내부 레이트를 8~96kHz로 제한하고 최종 장치 변환을 사용한다.
- 별도 음악·효과음 믹서를 64프레임씩 읽어 실제 합산 효과음 피크로 덕킹한다. 마지막 소프트 리미터는 유지한다.
- 백그라운드에서는 마스터를 음소거하고 효과음 소스를 종료한다. 음악 신스는 정지해 복귀 시 이어진다.

리샘플링은 변환 과정의 왜곡을 줄이는 처리이며, 저해상도 ADPCM에서 사라진 대역을 새로 생성하지 않는다. 실기기의 청취·발열·콜백 마감 시간은 별도 확인이 필요하다.

2026-10-22 호스트 측정은 `measurements.csv`에 저장했다. BGM 19곡 × 이전/새 44.1kHz/새 48kHz, 효과음 14개 × 새 44.1/48kHz를 검사했다. BGM RMS 변화는 −0.455~+0.103dB, 효과음은 이전 선형 보간 대비 +0.016~+0.700dB였다. BGM 리미터 전 최고 피크는 0.997537에서 1.011017로 바뀌며 최종 리미터가 이를 처리한다. 호스트 합성 시간 합계는 이전 대비 44.1kHz에서 1.28배, 48kHz에서 1.32배였다. 이는 실기기 CPU 측정이 아니다.
